{# ── 4. Identifier Explanation ─────────────────────────────────────────── #}

How resource identifiers work

{{ identifier_notice }}

local resource_id
The identifier meaningful within an adapter's source system (e.g. rooftop-1).
resource_type
The type/domain used to compose both the action and the resource id (e.g. ahu).
canonical resource_id
The typed identifier the gateway composes (e.g. ahu:rooftop-1).
resource_type + local_resource_id ↓ gateway ↓ canonical_resource_id

The gateway also accepts a direct, already-typed request shape: 

{
  "action": "read:ahu",
  "resource_id": "ahu:rooftop-1"
}

The console previews this composition for legibility; the gateway owns it. The broader action-domain vs. resource-type question is not resolved here.
