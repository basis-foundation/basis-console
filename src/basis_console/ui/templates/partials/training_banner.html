How the BASIS ecosystem fits together

Each component owns one responsibility. The console never crosses these boundaries — it observes, inspects, submits through the gateway, and explains.

basis-console
Observes, inspects, submits requests through the gateway, and explains the model. It does not decide.
basis-gateway
Enforces the boundary: authenticates the caller, composes canonical actions/resource ids, and is the single path to the kernel.
basis-core
Evaluates authorization (policy / roles / conditions) and produces the decision and audit evidence.
basis-adapters
Normalize OT/platform protocols (BACnet, Modbus, MQTT, …) into typed resources and actions.
basis-identity future
Identity (OIDC/JWKS/JWT/SAML/SCIM) belongs to the future basis-identity service. The console will display it, never implement it.
deploy / demo / topology future
Deployment packaging, demo data feeds, and topology views are future layers, not current console authority.

Operator → basis-console → basis-gateway → basis-core
